# CT-05 — Null speed

| | |
|---|---|
| **Case** | `CT-05` |
| **Specification** | [SPEC-SPD-001 §10](../spec/SPEC-SPD-001.en.md#ct-05--null-speed) v1.1.0 |
| **Reference data** | [`reference-data.csv`](../code/src/test/resources/reference-data.csv), line `CT-05` |
| **Discriminating** | **Yes** — it is the only case that leaves the nominal path |

## What it covers

| Item | |
|---|---|
| [`E-SPD-001`](../spec/SPEC-SPD-001.en.md#e-spd-001) | A leg has a speed `≤ 0` → reject |

## The data

| Leg | Distance | Speed | Duration |
|---|---|---|---|
| 1 | 60 km | 30.0 km/h | 2.000000 h |
| 2 | 40 km | **0.0 km/h** | — |

**Expected: the journey is rejected, with the business code `E-SPD-001`.**

Not a default value, not a skipped leg, not zero, not infinity: a **rejection carrying an
identifier the business itself named**.

## Why the case exists

A speed of zero means the vehicle never arrives. There is no average speed to publish —
the question has no answer, not a hard one.

The valid leg comes **first** on purpose. An implementation that validates lazily, leg by
leg while accumulating, has already added 60 km and 2 h to its totals by the time it meets
the bad one. If the check is missing entirely, `60 ÷ 0` gives — depending on the numeric
type — a division-by-zero exception, or `Infinity`, which propagates into a total duration
of `Infinity` and a published average speed of **0.0 km/h**. That last one is the dangerous
outcome: a plausible number, no error, no trace.

The specification places this in `PRECONDITIONS`, so the rejection happens **before** any
arithmetic. The reference implementation scans every leg first, and only then accumulates.

> **Why `≤ 0` and not `= 0`.** A negative speed is not a slower vehicle, it is corrupt
> input. Both are rejected by the same rule, and `E-SPD-001` is stated on the bound rather
> than on the single value zero.

## What it does not test

Everything about the nominal path: no total is computed, no average is published, no
invariant is evaluated. The [test report](../reports/TEST-REPORT.md) marks this case
`rejected as expected` and nothing else — it contributes exactly one item to the coverage
table, and it should not be read as contributing more.

**No case tests a negative speed.** `E-SPD-001` is written on `≤ 0`, and only `= 0` is
exercised. That is a genuine hole, small and known.
