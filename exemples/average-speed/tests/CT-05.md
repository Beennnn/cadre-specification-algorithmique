# CT-05 — Null speed

| | |
|---|---|
| **Specification** | [§10](../spec/SPEC-SPD-001.en.md#ct-05--null-speed) |
| **Data** | [`reference-data.csv`](../code/src/test/resources/reference-data.csv), line `CT-05` |
| **Covers** | [`E-SPD-001`](../spec/SPEC-SPD-001.en.md#e-spd-001) |

60 km at 30.0 km/h, then 40 km at **0.0 km/h** → rejected, code `E-SPD-001`.

**What it catches.** A missing precondition. Without it, `60 ÷ 0` gives — depending on the
numeric type — an exception, or `Infinity`, which propagates into a total duration of
`Infinity` and a published speed of **0.0 km/h**: a plausible number, no error, no trace.
The valid leg comes first on purpose, so a lazy validation has already accumulated when it
meets the bad one.

**What it lets through.** The whole nominal path. And a **negative** speed: `E-SPD-001` is
written on `≤ 0` and only `= 0` is exercised — a small, known hole.
