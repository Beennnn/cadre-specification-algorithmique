## The data

`target_batch_mass = 1.001 kg`, `balance_step = 0.001 kg`

| Component | Fraction | Nominal | Rounded | **Weighed** |
|---|---|---|---|---|
| `CMP-A` | 0.400000 | 0.400400 | 0.400 | **0.401** |
| `CMP-B` | 0.400000 | 0.400400 | 0.400 | **0.400** |
| `CMP-C` | 0.200000 | 0.200200 | 0.200 | **0.200** |

Sum of rounded `= 1.000` → `residual = +0.001`. `CMP-A` and `CMP-B` are **tied** on the
largest fraction; the tie-break takes the smallest identifier, `CMP-A`.
**Final sum = 1.001 kg.**

## Why the case exists

It was **built in order to** create the tie. No natural batch produced one, and without it
the tie-break clause of `RG-050` was covered by nothing.

An implementation with no tie-break is not obviously broken. It picks *a* maximum — the
first one the collection yields — and every invariant holds: the sum is right, the doses
are whole steps, none is negative. It passes CT-01, CT-02, CT-04, CT-05 and all four
rejection cases. **It is wrong only in that the answer depends on the order the components
were entered**, which is precisely the property `INV-04` forbids and the kind of defect
that surfaces months later as "the same batch gave two different sheets".

> **The tie-break is a business decision, not a coding convention.** Whether the extra gram
> goes to `CMP-A` or `CMP-B` changes a weighed mass, so `RG-050` names it, and `Q-02` —
> now closed — records that a per-component priority order was considered instead.

The implementation earns a comment for it, because the Java is counter-intuitive: `max()`
keeps the *last* of the equals, so identifiers are ordered **descending** for the smallest
to win.

## What it does not test

| | |
|---|---|
| The residual bound | One step against `P-02 = 3` |
| A tie between more than two | Only two components are tied. Three would exercise nothing new here, but it is untested |
| The tie on the *smallest* fraction | `RG-050` only ever looks at the largest |

> `INV-04` is listed as covered by this case, but the case alone does not establish it.
> Three components admit six orderings; the harness runs **200 random permutations** on
> this exact input. A property that must hold for every input is not settled by one row of
> a table — see [the test report](../reports/TEST-REPORT.md).
