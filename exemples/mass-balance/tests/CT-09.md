# CT-09 — Residual over the bound

| | |
|---|---|
| **Case** | `CT-09` |
| **Specification** | [SPEC-MAS-001 §10](../spec/SPEC-MAS-001.en.md#ct-09--residual-over-the-bound) v1.1.0 |
| **Reference data** | [`reference-data.csv`](../code/src/test/resources/reference-data.csv), line `CT-09` |
| **Discriminating** | **Yes** — it is the only case that rejects on the residual |

## What it covers

| Item | |
|---|---|
| [`E-MAS-002`](../spec/SPEC-MAS-001.en.md#e-mas-002) | The residual exceeds `P-02` balance steps → reject |
| [`RG-040`](../spec/SPEC-MAS-001.en.md#rg-040--acceptability-of-the-residual) | Acceptability of the residual, **above** the bound |

## The data

`target_batch_mass = 1.400 kg`, `balance_step = 0.100 kg` — fourteen steps.

Ten components, fraction `0.100000` each (they sum to exactly 1).

```
nominal per component = 1.400 × 0.100000 = 0.140 kg = exactly 1.4 steps
rounded               = 1 step           = 0.100 kg
sum of rounded        = 10 × 0.100       = 1.000 kg
residual              = 1.400 − 1.000    = +0.400 kg = 4 steps
```

Four steps is **more than `P-02` = 3**. **Expected: rejected with `E-MAS-002`, reporting
the residual found.**

## Why the case exists

Because until v1.1.0, `E-MAS-002` was exercised by nothing.

The rule was stated in §9, implemented in the code, and listed in the coverage table. Eight
cases ran through it and not one crossed the bound: the largest residual in the whole set
was [CT-05](CT-05.md)'s, sitting **exactly on** three steps and accepted. **Delete the
residual check entirely and every case still passed.** The coverage report is what said so
— it prints, item by item, what the run did not exercise, and `E-MAS-002` came back
`**NO**`.

Building the case took some arithmetic. Rounding loses at most half a step per component,
so exceeding three steps needs enough components each losing enough. Ten components whose
nominal dose is exactly 1.4 steps each lose 0.4 step — four steps in total, one past the
bound, with no component near a rounding tie.

> **CT-05 and CT-09 are a pair.** One sits on the bound and is accepted, the other one step
> past it and is refused. Together they pin down both the **value** of `P-02` and the
> **strictness** of the comparison in `RG-040`. Either alone leaves half of that
> unverified.

## What it does not test

| | |
|---|---|
| The value 3 itself | The pair shows the boundary lies between 3 and 4 steps; that `P-02` should *be* 3 is a business decision, not a testable one |
| The reported residual | The harness checks the error code, not the message. An implementation reporting the wrong residual value would pass |
| The nominal path | The batch is rejected before any allocation |
