## The data

`target_batch_mass = 1.000 kg`, `balance_step = 0.001 kg`

| Component | Fraction | Nominal | Rounded | **Weighed** |
|---|---|---|---|---|
| `CMP-A` | 0.166667 | 0.166667 | 0.167 | **0.167** |
| `CMP-B` | 0.166667 | 0.166667 | 0.167 | **0.167** |
| `CMP-C` | 0.666666 | 0.666666 | 0.667 | **0.666** |

Sum of rounded `= 1.001` → `residual = −0.001` → **taken from** `CMP-C`.
**Final sum = 1.000 kg.**

## Why the case exists

Because rounding can overshoot, and half the plausible implementations quietly assume it
cannot.

`RG-030` defines the residual as `target_batch_mass − SUM OF dispensed_mass` — a **signed**
quantity. Written as a gap, a shortfall, or "what is left to distribute", it invites an
absolute value, and an absolute value is wrong here in the loudest possible way: it would
add 0.001 kg to `CMP-C` instead of removing it, giving a batch of 1.002 kg — two steps
away from target, and `INV-01` catches it immediately.

The quieter failure is a type that cannot hold the sign at all. An implementation counting
steps in an unsigned integer, or clamping at zero "because a residual is a leftover", turns
−1 step into 0 and weighs 1.001 kg.

`CMP-C` is the largest fraction *and* the one that was rounded up, so the correction lands
on the component that caused it. That is not a coincidence the rule guarantees — it is a
property of this data — but it does mean the case reads naturally.

## What it does not test

| | |
|---|---|
| The tie-break | `CMP-C` is the strict maximum. See [CT-03](CT-03.md) |
| A negative dose | `INV-03` is checked and holds, but the residual here is far too small to drive any dose below zero. **No case in the set does that** — `RG-040` is supposed to reject first, and no case verifies that it really does |
| The bound | One step against `P-02 = 3` |
