## What it covers

## The data

`target_batch_mass = 1.000 kg`, `balance_step = 0.001 kg`

| Component | Fraction | Nominal | Rounded | **Weighed** |
|---|---|---|---|---|
| `CMP-A` | 0.500000 | 0.500000 | 0.500 | **0.500** |
| `CMP-B` | 0.250000 | 0.250000 | 0.250 | **0.250** |
| `CMP-C` | 0.250000 | 0.250000 | 0.250 | **0.250** |

Every nominal mass is already a whole number of steps. `residual = 0.000` — `RG-050`
changes no dose. **Final sum = 1.000 kg.**

## Why the case exists

For the **degenerate value**. Zero is where conditional code goes wrong: an allocation
written as "add the residual to the receiver" is harmless here, but one written as "adjust
the receiver by at least one step", or one that treats a zero residual as an anomaly to
report, is not.

It also fixes the reference point. Every other nominal case moves mass around after
rounding; this one proves that when nothing needs moving, **nothing moves**. A dose that
changed here would mean the allocation fires unconditionally.

Note the tie between `CMP-B` and `CMP-C`: it exists but is never resolved, because
`RG-050` looks for the *largest* fraction and that is `CMP-A`, alone. The case therefore
touches the tie-break without exercising it — a distinction worth keeping straight when
reading the coverage table.

## What it does not test

| | |
|---|---|
| Rounding | No nominal mass has a fractional number of steps |
| The residual, in any direction | It is zero |
| The bound, the tie-break, any rejection | None is reached |

**This is the least discriminating nominal case in the set.** It is kept because zero is a
boundary, not because it detects the mistakes this specification is about.
